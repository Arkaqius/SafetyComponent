# Implementation Plan: Provider Selection and Monitoring States

**Branch**: `open_spec_intruduction` | **Date**: 2026-11-13 | **Spec**: [spec.md](spec.md)

**Input**: `docs/features/002-provider-selection-states/spec.md`

## Summary

Replace inherited provider enablement with one explicit plugin-or-disabled
selection per capability. Keep provider parameters separately so switching the
selector retains draft values. Remove the affected compatibility paths rather
than supporting both source models.

Publish applied selection independently of C-EXT activation. SafetyHome shall use
that runtime truth to keep disabled sections visible and muted, and to distinguish
a fresh healthy zero from absent evidence. Add an explicitly selected German
synthetic warning provider whose results reach a separate test preview and never
real safety evaluation, coverage, notifications or recovery.

## Technical Context

**Language/Version**: Python 3.10+ backend (local 3.10.5, App image 3.12);
TypeScript strict mode; Node 20 frontend (default local Node is 18.20.8, use
isolated Node 20 for checks).

**Primary Dependencies**: Existing AppDaemon 4.x, Pydantic 2, PyYAML, React 19,
Vite 6, @hakit/core and React Router. No new framework or external warning service.

**Storage**: Existing private YAML and revisioned atomic saves; the existing SQLite
store gains one bounded C-EXT assertion checkpoint namespace. MQTT publishes
applied selection and separate preview state. No new database or legacy importer.

**Testing**: pytest/AppDaemon Hass stub, Ruff, scoped mypy, Node tests, TypeScript,
ESLint, Prettier and mock-only Playwright desktop/mobile Chromium.

**Target Platform**: Existing Home Assistant App / AppDaemon backend and Ingress UI.

**Project Type**: Existing backend/frontend safety-monitoring application.

**Performance Goals**: Preserve bounded workers, per-provider scheduling, response
and metadata limits. Selectors update synchronously in the local draft; initial
application of selection precedes polling. Dummy polling performs no network I/O
or sleeps. No network work or waiting loops are added to safety callbacks;
assertion persistence uses bounded transactions in the existing local store.

**Constraints**: One home, three existing capabilities, one selected source per
capability; zero legacy source aliases/inheritance controls/migration flows;
synthetic evidence cannot alter real H/D state or coverage; no household actions
in acceptance. Preserve safety thresholds and consent boundaries.

**Scale/Scope**: Two operator screens plus compiler/API/runtime/provider seams,
one German dummy, three independently editable categories. Existing catalogue
limits (64 providers, 1 MiB, bounded schemas) remain controlling.

## Phase 1: Design

- [Source selection](contracts/source-selection.md): explicit category map,
  canonical parameter map, metadata v2, strict validation and unchanged routes.
- [Monitoring presentation](contracts/monitoring-presentation.md): boot-scoped
  applied selection, muted disabled state and separate historical/active evidence.
- [Synthetic provider](contracts/synthetic-provider.md): trusted declaration,
  no HTTP transport, deterministic scenarios, separate event/preview boundary.
- [Data model](data-model.md): source, resolved binding, applied snapshot and state
  transitions; [ADR-0002](../../adr/0002-explicit-provider-selection.md) records why.

### Implementation sequence for task generation

1. Add failing source/compiler/API tests for the new shape and rejection of old
   fields. Add trusted declaration and synthetic-routing isolation tests.
2. Replace source selection and normalization, regenerate schemas, update all
   public examples and sanitized shared fixtures together. Remove obsolete
   tests/fixtures and alias/provenance implementation within this feature's scope.
3. Publish authoritative applied selection before polling, including component-off
   cases. Keep real diagnostics/degradation restricted to selected live providers.
4. Add a bounded real-assertion checkpoint and restore it before initial fault
   publication. Cover source-disable/component-off/dummy-selection restarts;
   retain unresolved real hazards without replaying timers, notifications or actions.
   Publish retained_assertions/retained_hazard_unknown on real fault entities and
   carry bounded retained context into global coverage. Exclude external exposure
   proposal IDs when RecoveryManager restores persisted state.
5. Add the German dummy and synthetic event/preview path, proving every scenario
   has zero effect on real safety state, advice inhibition, notifications and recovery.
6. Replace frontend intent/alias helpers with category choices and canonical
   parameter editing. Update metadata client and development mocks together.
7. Decode applied selection and preview separately. Revise every category summary,
   counter, source card and empty state, not only the official-warning list.
8. Update Polish guide/help, neutral CSS and runtime EN/PL/DE labels; finish full
   cross-layer acceptance and review source-state transitions.

Backend contract work precedes UI wiring. Separate test files and documentation
can run in parallel once their shared contracts are fixed; edits to the same file
remain sequential. This command produces no task checklist or production edits.

## Complexity Tracking

No unapproved constitution exception. Two intentional design boundaries are
necessary: a canonical category-selection map removes inheritance ambiguity;
a separate synthetic event/preview prevents test data from reaching real safety
consumers. Both reuse the existing runtime rather than adding an application.
A bounded assertion checkpoint is also required by FR-010: current fault objects
start empty on restart and the existing evidence journal is not a complete
exposure snapshot. Reusing that first-frame journal alone could publish a false
clear. The checkpoint uses the existing SQLite store, not a persistence framework.
